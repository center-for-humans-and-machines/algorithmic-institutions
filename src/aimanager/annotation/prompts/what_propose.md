# Task: build a codebook of manager mechanisms

Below is a numbered list of short descriptions of mechanisms that manager rules use (what a manager does to players). Many describe the same mechanism in different words. Group them into a codebook of distinct mechanisms.

Guidelines:
- A code is one mechanism at the level of what the manager does to players, e.g. "punish shortfall relative to group mean", "cap on punishment per player", "no punishment late in the game". It must be specific enough that one can decide for any rule whether it implements the code.
- Codes should not overlap: an item should fit exactly one code. Prefer merging near-duplicates over splitting by minor variants (different thresholds or scales of the same idea are one code).
- Cover the frequent mechanisms; rare idiosyncratic items may stay without a code.
- `name`: short snake_case identifier; `label`: a few words; `definition`: one or two sentences saying what counts; `fits`: two short examples that fit; `does_not_fit`: one or two near misses that belong elsewhere.
