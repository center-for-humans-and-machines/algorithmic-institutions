The per-group virtual node: the group becomes a member

Spoon-feeding detected

A setting inside this method was chosen by the analyst rather than measured from the data, and the value chosen is the one that makes the result look best. Nothing here broke a rule and no result is wrong — every choice below is written down openly in the experiment's own log. It is flagged because the same choice was made three times across both stacks, always in the same direction.

The third time this number came up, the estimate was 0.618 — a perfectly usable value, meaning a group's mood fades noticeably from one round to the next. It was set to 1.0 anyway, under a rule written back when the estimate had been off the scale. The log is candid about it: “a rule written for a saturating estimate is now being applied to one that is not.”

The campaign later ran both settings and published the comparison. At 1.0 the target row scores 0.90; at the measured 0.618 it scores 1.22 — a whole grade worse. So the setting that was kept is the setting that wins, and the reason given for keeping it is that an earlier experiment had scored better with it — not that anyone measured real groups behaving that way.

The problem

Even with the herding copula bolted on at the sampling step, the network itself had nowhere to store 'how this group is doing': information between members passed through a single averaging step per round, and slowly-building group identity had no carrier. The group-spread row (CG) still read 4.27 and the switching-pull row (RCD) 2.76.

The change

A textbook remedy from the graph-network literature (Gilmer et al. 2017's 'master node'): each group gets a virtual member that aggregates everyone after message passing, keeps its own GRU memory from round to round, and broadcasts its state back to all members at the next round. Group state is now computed inside the network instead of imitated by correlated dice -- the copula remains only as a final light touch, recalibrated to rho = 0.044.

The maths, in plain English

  1. Background in one sentence: the contribution network computes a representation (a vector of numbers) per player each round, lets players exchange information along connections, and gives each player a small recurrent memory -- but no object in the network IS a group.
  2. Each round, after the players have exchanged their messages: average the representations of each group's current members into one vector, and append the group's share of the population (members / 8) -- without that number, an average over 2 members and an average over 6 would look like the same state of the world.
  3. Feed that vector into a GRU -- a small recurrent memory unit that keeps a hidden state and updates it each time it sees a new input. There is one hidden state per group per episode (the learned update rule itself is shared), so the state becomes the group's running summary of everything its members have been doing.
  4. Broadcast: each member's own representation gets the group state attached to it just before the final layer that scores the 21 contribution levels. Every member of a group reads the SAME state -- which is what lets the whole group move coherently.
  5. Membership is looked up fresh every round, so a player who switches groups starts reading the new group's memory from the switch round on. That is the mechanism behind a pattern measured in the human data: new arrivals weight the receiving group's recent history at 0.28.
  6. No new training objective: the ordinary per-player prediction loss simply flows backwards through the broadcast and the averaging, so the group state learns to contain exactly whatever helps predict its members. (Edge case handled: an emptied group keeps its state ticking on zero input; nobody reads it until someone moves in.)
