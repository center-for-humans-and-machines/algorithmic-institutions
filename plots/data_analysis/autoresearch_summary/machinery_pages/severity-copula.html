The severity copula: one punishment mood per group

correlated-sampling installed by PR #160 · punisher bay of both machines

The problem

In the human games, everything a group is punished in a round comes from one manager making one decision: when the manager is harsh, everyone feels it. The simulation instead drew each member's punishment separately, like eight independent dice, so simulated managers never had moods. The spread between group punishment averages (row PD) was pinned far below the human level, and no retraining could fix it -- it is a property of how the dice are thrown, not of the model.

The change

Keep each member's predicted punishment probabilities exactly as they are, but couple the dice. Every group-round gets one shared 'severity' random number, mixed with a little per-member noise (mixing weight rho = 0.35, estimated from the human data), and each member's mixed number is translated back through their own predicted distribution. Individual histograms are untouched by construction -- only the togetherness of the draws changes.

The maths, in plain English

  1. Start from what the model already outputs: for each group member, 31 probabilities -- one for every punishment level 0 to 30. None of these numbers are changed.
  2. Normally a member's punishment is drawn by rolling one random number u between 0 and 1 and walking up their probabilities until the running total passes u. Independent rolls for everyone is what kept the groups too uniform -- so the only thing this unit changes is where u comes from.
  3. Each round, draw one shared bell-curve number g for the whole group (the manager's 'mood' that round) and one private bell-curve number e for each member. Blend them: w = sqrt(0.35) x g + sqrt(0.65) x e. Because 0.35 + 0.65 = 1, the blend w behaves exactly like a single fresh bell-curve draw -- that is the whole trick.
  4. Convert each member's w back into a 0-to-1 number u (the standard bell-curve-to-uniform conversion) and use it as their roll. Each member still lands on every punishment level exactly as often as their own probabilities say. What changed: when the shared g is high, everyone's roll is high together -- harsh rounds are harsh for the whole group.
  5. The strength 0.35 is not a guess. In the training games, count how often two groupmates were BOTH punished harder than their individual probabilities can explain. Independent rolls predict a certain number of such coincidences; the human data has clearly more. Slide the dial (called rho) from 0 upward and keep the value that makes the observed coincidences most plausible -- a maximum-likelihood fit. It lands at rho = 0.3508.
  6. Where it plugs in: after the model, at the last step of the simulation loop. The model is not retrained; setting rho = 0 gives back the old independent sampling, byte for byte.

Where it lives in the code

  • scripts/baselines/punishment_copula_rho.py — estimates rho from the training games (pairwise MLE)
  • src/aimanager/simulation/linear_ah.py — the sampler: reads copula_rho off the .joblib bundle and couples the draws; rho = 0 restores independent sampling bit-for-bit

What it bought

PD 2.93 -> 1.53, a full band closer to the human data, with the stack mean falling 1.76 -> 1.69. This change first landed as PR #146, was unmerged for process reasons, and was redone cleanly as PR #160 -- one method, counted once. It sits unchanged in both machines' punisher bays.
