One-hot group sizes: every size gets its own dial

feature-engineering installed by PR #174 · plate on the joint exodus head, gaussian-MLP machine

The problem

The joint head read the two group sizes as raw numbers, which forces a straight-line effect: a group of 6 must matter exactly twice a group of 3. A sibling experiment on the contribution slot (PR #173) showed numeric size coding only travels half the distance -- size effects are not linear.

The change

The two size inputs are re-encoded as one-hot codes, so each possible size level gets its own learned weight. Everything else in the head is byte-identical.

The maths, in plain English

  1. Before: each group's size entered the exodus head as one scaled number (size / 8). A single number times a single learned weight forces a straight-line effect -- going from 2 to 4 members must matter exactly as much as going from 4 to 6.
  2. After: the size becomes a 9-position indicator ('one-hot'): size 3 is encoded as 0,0,0,1,0,0,0,0,0. Each position has its own learned weight, so the head can express, say, that the step from 2 to 3 members changes everything while the step from 5 to 6 changes almost nothing.
  3. The two size inputs become 18 inputs; the head, its training procedure, and every other feature stay byte-identical -- which is also why the improvement is attributable to the encoding change alone.
